## 1. Видение

Система принимает сетевые события (flow + payload), прогоняет их через **ансамбль
нейросетей-экспертов** (Mixture-of-Experts), мета-слой выдаёт вердикт
`(класс атаки, severity, confidence)`, а детерминированный **SOAR-движок** предлагает
реакцию, которую аналитик подтверждает через **SOC-консоль (React UI)**.

Ключевой принцип разделения:
- **Нейросети** отвечают на «*что* происходит» (вероятностно).
- **SOAR (правила)** отвечает на «*что делать*» (детерминированно, объяснимо, обратимо).

## 3. Данные — ГИБРИДНАЯ стратегия

Публичные и самосгенерированные данные играют **разные роли** (не дублируются):

| Источник | Роль | Что именно |
|---|---|---|
| **Публичные датасеты** | обучение сетевых моделей (объём, разнообразие, сравнимость с бенчмарками) | Эксперты 1–4 |
| **Свой лаб-датасет** (автономный полигон) | (1) **живое демо** = сам поток трафика; (2) **валидация end-to-end** на реальном пайплайне (train/serve consistency); (3) **обучение HIDS** (Эксперт 5 — Sysmon-логи, тут он первичен); (4) **held-out zero-day** для проверки автоэнкодера | runtime + Эксперт 5 + тесты |

> Вывод: свой датасет — НЕ замена публичным по объёму, а отдельные незаменимые функции
> (демо, доказательство работоспособности, HIDS, zero-day). Стоимость почти целиком «зашита»
> в стоимость полигона, который и так нужен для живого демо.

### Источники по экспертам

| Эксперт | Датасет | Что покрывает |
|---|---|---|
| 1. Flow | **UNSW-NB15** | широкий спектр: DoS, Exploits, Recon, Fuzzers, Backdoors, Worms, Shellcode, Generic |
| 2. Temporal | **CTU-13** | реальные ботнеты, beaconing, временные паттерны (LSTM раскрывается) |
| 3. Payload | **CSIC 2010 HTTP** | SQLi, XSS, web brute force (контент пакета) |
| 4. Anomaly | «норма» (benign) из flow-датасетов | обучение автоэнкодера, zero-day/unknown |
| 5. Host (HIDS) | **DARPA OpTC (подмножество)** + свои Sysmon-логи из лаборатории | действия на хосте: выполнение команд, lateral movement, persistence (раскрывает Caldera) |

> ⚠️ OpTC полностью огромен (сотни ГБ–ТБ eCAR) — берём **subset** (несколько хостов/дней), не весь корпус.

Риски данных: дисбаланс классов → focal/weighted loss, метрика **PR-AUC** (не accuracy).
Корректный временной сплит, чистка дубликатов, защита от ликеджа.

> ⚠️ **Train/serve consistency:** фичи из живой лаборатории считаем **тем же экстрактором**,
> что и при обучении (**nfstream** для flow), иначе модель «увидит» другие признаки, чем училась
> (train/serve skew — частая причина провала live-NIDS). По возможности обучаем на фичах,
> пересчитанных из PCAP, а не на «чужих» CSV.

## 4. Детекция — 4 эксперта + мета

- **Эксперт 1 — Flow CNN+LSTM:** `[B, N, F]` → TimeDistributed Conv1D → LSTM → softmax (мультикласс).
- **Эксперт 2 — Temporal CNN+LSTM:** окна потоков по времени, фокус на периодичности (beaconing) и медленных атаках.
- **Эксперт 3 — Payload char-CNN / мини-Transformer:** байты/строки запроса → класс web-атаки.
- **Эксперт 4 — CNN-LSTM Autoencoder:** учится на benign, reconstruction error > порог ⇒ аномалия.
- **Эксперт 5 — Host CNN+LSTM (HIDS):** последовательности хостовых событий (Sysmon/auditd) →
  детект действий противника на самой машине (выполнение команд, persistence, lateral movement).
  Добавляется **отдельной фазой после NIDS** — раскрывает Caldera на 100%.
- **Мета-слой:** stacking-классификатор (логрег/бустинг) над выходами экспертов
  + open-set логика (эксперты не уверены **и** AE даёт высокий скор ⇒ `UNKNOWN/zero-day`)
  + **корреляция сеть ↔ хост** (один инцидент из сетевого и хостового сигналов)
  + severity-движок (класс → критичность, дедуп, агрегация в инцидент).

Окна: группировка по `src IP` + сортировка по времени, старт **N=16, stride=1**
(подберём эмпирически). Метка окна: класс последнего потока.

Обучение: PyTorch + CUDA 12.x + AMP на RTX 3060 Ti (8 ГБ). Инференс — **ONNX на CPU** внутри ВМ.

**Scope:** гибрид **NIDS + HIDS**, строим последовательно: сначала сетевые эксперты (1–4) до
рабочего end-to-end, затем хостовой эксперт (5) + корреляция.

## 5. Reaction — SOAR (детерминированный, без нейросетей)

- **Режим:** СИМУЛЯЦИЯ (ничего реально не блокируется; действия пишутся в аудит и показываются в UI).
- **Подтверждение:** human-in-the-loop — аналитик жмёт Approve/Reject в очереди реагирования.
- **Tiers действий:** 0 лог/обогащение → 1 уведомление → 2 мягкий (rate-limit/watch) →
  3 жёсткий (блок IP, симуляция) → 4 сдерживание (изоляция, только вручную).
- **Playbooks по классам:** PortScan → watch; Brute force → блок по N попыткам (fail2ban-паттерн);
  DDoS → агрегация + rate-limit; Bot/C&C → блок назначения + изоляция; UNKNOWN → только алерт.
- **Предохранители:** whitelist (шлюз/DNS/админ-IP), TTL + авто-откат, cooldown/дедуп,
  полный аудит-лог, высокий порог confidence на tier 3.
- **MITRE ATT&CK:** маппинг классов атак на техники (T-коды) для UI-матрицы.
- **Каналы уведомлений:** UI (всегда) + **Email (SMTP)** + **Webhook** (универсальный: Slack/Discord/Teams/Telegram).

## 5.5 Demo / Cyber Range (демо-стенд)

> ⚠️ Всё — **только в изолированной лабораторной сети** (host-only/internal, без интернета),
> против **своих** намеренно уязвимых целей. Авторизованное тестирование в песочнице.

**Топология — 2 ВМ под Hyper-V (Win11 Pro), ~16 ГБ RAM:**

```
   ВМ-АТАКУЮЩИЙ (Kali + Caldera-сервер) ──host-only сеть──► ВМ-SIEM (она же жертва)
   nmap/hydra/hping3/sqlmap + ATT&CK-сценарии              ├─ уязвимые сервисы-цели (Juice Shop/DVWA)
   одной кнопкой                                           ├─ NIDS: захват трафика (tcpdump/nfstream)
                                                           ├─ HIDS: свои логи (Sysmon)
                                                           ├─ детект (ONNX, CPU) → мета → SOAR
                                                           └─ FastAPI + React UI (Approve/Reject)
```

- **Жертва объединена с SIEM-ВМ** — укладываемся в 16 ГБ без третьей машины.
- **Гипервизор:** Hyper-V (нативен в Win11 Pro, дружит с WSL2/Docker, есть checkpoints/снапшоты
  для отката чистой жертвы между демо).
- **GPU:** только на этапе обучения (на хосте) → ONNX → CPU-инференс в ВМ.
- **Генерация атак:** **MITRE Caldera** (автоматические ATT&CK-цепочки, beaconing → Эксперт 2/5,
  наполняет MITRE-матрицу) + сетевые тулзы для «шумных» атак (скан/DoS/brute/web).
- **3 режима демо:** (A) replay датасета — для CI/регресса; (B) Docker-лаб — воспроизводимо;
  (C) ВМ-стенд — реалистично. Управление ресурсами — через docker-compose **profiles**
  (`demo` / `full` / `train`), чтобы не поднимать весь зоопарк сразу.
- **Benign-фон:** **GHOSTS** (CMU SEI) — симулятор «живых пользователей» (NPC: браузинг, почта,
  файлы) для правдоподобной «нормы» (самый сложный пункт) + автоэнкодер.
- **Разметка live-данных:** ground-truth по расписанию атак (знаем, когда что запускали).
- **Автономная генерация («датасет как код»):** оркестратор в цикле — откат снапшота → захват
  (tcpdump + Sysmon) → проигрывание timeline (GHOSTS-фон + Caldera/сетевые атаки) → стоп →
  авто-разметка по таймлайну → nfstream-фичи + хост-логи → рандомизация → повтор. Работает
  **офлайн и unattended** (интернет нужен только для первичной установки инструментов).

## 6. UI — SOC-консоль (8 экранов)

Дизайн: **Figma** (макеты) → реализация **React + TypeScript + Tailwind/shadcn**,
real-time через WebSocket.

1. **Overview** — счётчики, severity-распределение, график во времени, топ src IP.
2. **Лента алертов** — поток инцидентов (время, src→dst, класс, severity, confidence).
3. **Карточка инцидента** — детали + какой эксперт сработал и его уверенность + обогащение (GeoIP/reputation).
4. **Очередь реагирования** — предложенные действия с Approve/Reject (human-in-the-loop).
5. **Аудит-лог** — что предложено/сделано, кто подтвердил, откаты.
6. **Модели/метрики** — per-class precision/recall, confusion matrix, ROC, состояние моделей.
7. **MITRE ATT&CK Matrix** — подсветка сработавших техник.
8. **Threat Hunting / Search** — поиск по логам (OpenSearch).

## 12. Журнал решений и обоснований (почему именно так)

Это «память» проекта — чтобы при возвращении не переоткрывать споры.

- **Почему ансамбль (Mixture-of-Experts), а не одна модель?** Разные атаки живут в разных
  представлениях: DoS/скан — в статистике потоков, боты — во временной периодичности,
  SQLi/XSS — в payload, хостовые действия — в логах ОС. Одна модель видит один срез.
  Плюс сильный дисбаланс и open-set (нужно уметь сказать «это новое»).
- **Почему CNN+LSTM?** CNN — локальные паттерны внутри потока; LSTM — временные зависимости
  между потоками (beaconing, медленный скан, нарастающий DoS). Требует **нарезки в окна**
  (группировка по src IP + сортировка по времени) — без этого LSTM нечего «помнить».
- **Почему гибрид публичные + свой датасет?** Публичные дают объём, разнообразие и
  сравнимость с бенчмарками; свой полигон даёт живое демо, проверку на реальном трафике
  (train/serve consistency), обучение HIDS и held-out zero-day. Это РАЗНЫЕ роли, не дубль.
- **Почему свой датасет всё-таки нужен (хотя «почти не используется» для обучения сети)?**
  Его стоимость зашита в полигон, который нужен для живого демо; а функции (демо, валидация,
  HIDS-обучение, zero-day) публичными не закрываются.
- **Почему CIC-IDS2017 отвергнут?** Баги CICFlowMeter, дубликаты, ликедж → нестабильное
  обучение и завышенные метрики.
- **Почему train/serve consistency критична?** Модель учится на фичах из CSV, а в лаборатории
  трафик превращается в фичи другим инструментом → признаки не совпадают → детект не работает.
  Решение: один экстрактор (**nfstream**) и для обучения (из PCAP), и для live.
- **Почему Response — НЕ нейросети?** Реакция должна быть предсказуемой, объяснимой,
  обратимой — это правила/политики (SOAR), а не вероятности.
- **Почему симуляция + подтверждение аналитиком?** Безопасно (не отрежем себе сеть),
  и human-in-the-loop требует UI → UI стал обязательным, а не украшением.
- **Почему ONNX + CPU-инференс в ВМ?** Проброс GPU в ВМ — боль; обучаем на хосте (GPU) →
  экспорт ONNX → лёгкий CPU-инференс в ВМ. Это ещё и честный production-паттерн.
- **Почему 2 ВМ и Hyper-V?** 16 ГБ RAM: полный стек + тяжёлые ВМ одновременно не влезут,
  поэтому обучение и демо разнесены во времени, демо гоняет лёгкий срез (docker profiles).
  Hyper-V нативен в Win11 Pro, дружит с WSL2/Docker (без конфликтов VirtualBox), есть снапшоты.
- **Почему Caldera + GHOSTS?** Caldera — автоматизация ATT&CK-атак (хостовая активность,
  beaconing, наполняет MITRE-матрицу); GHOSTS — правдоподобный benign-фон (самый сложный
  пункт для автоэнкодера). Объёмные сетевые атаки — сетевыми тулзами (nmap/hydra/hping/sqlmap).
- **Почему DARPA OpTC только подмножеством?** Полный корпус — сотни ГБ–ТБ, на 16 ГБ нереально.
- **Цель проекта — портфолио:** отсюда «всё в Core» и максимум маркетируемых технологий
  (ML + Backend + Frontend + Data + DevOps + Security), но строим инкрементально, чтобы на
  каждом шаге был демонстрируемый результат.
