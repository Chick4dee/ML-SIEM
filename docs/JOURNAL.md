## 2026-06-07 — Фиксация плана

Согласован и зафиксирован полный план проекта (PLAN.md): гибридный SIEM/SOAR
(NIDS + HIDS), 5 нейро-экспертов + мета-слой, SOAR на правилах, React SOC-консоль,
демо-полигон на Hyper-V. 22 фазы. Проанализированы уроки предыдущего проекта (v1)
и 12 системных рисков консистентности train/serve (раздел 10.5 плана).

## 2026-06-12 — Актуализация плана

По итогам ревизии в план внесены правки:
- Убрано устаревшее обоснование «ONNX + CPU-инференс в ВМ» (рудимент старой
  топологии; в Варианте A инференс на GPU хоста, ONNX опционален).
- Добавлен риск #13: работоспособность nfstream на Windows — проверять
  smoke-тестом на фазе 0, до того как на нём построен весь пайплайн.

  не ждёт React UI фазы 13).
- Решено: DVC-remote — локальный диск; в публичный репозиторий только
  `.dvc`-указатели.

**Smoke-тест nfstream на Windows (риск #13) — ПРОЙДЕН:**
- Установка nfstream 6.6.0 — ок, но движок требует **Npcap**
  (установлен вручную, WinPcap API-compatible mode).
- Парсинг PCAP — ок (эталонный файл, nDPI распознал TLS).
- **Live-захват с физического адаптера — ок**, без прав администратора.

  vNIC Hyper-V — перепроверить на фазе 17.

## 2026-06-12 — Фаза 1: данные и фичи (В РАБОТЕ)

**Датасеты** (`A:\datasets\`):
- CSIC 2010 (web-атаки, для Эксперта 3) — скачан с зеркала, проверен:
  сырые HTTP-запросы, в аномальных — SQLi/XSS.
- CTU-13 (13 ботнет-сценариев, для Эксперта 2) — скачан (1.86 ГБ) и распакован:
  в каждом сценарии ботнет-PCAP + ground-truth `.binetflow` (+ образец малвари —
  не запускать!).
- UNSW-NB15 (~100 ГБ PCAP + CSV GT, для Эксперта 1) — качается;
  Argus/BRO-выгрузки авторов сознательно не берём (контракт #1: фичи считаем
  сами, nfstream'ом).

**Модуль `features/extractor.py`** — переэкстракция PCAP → потоки (86 фич) через
nfstream с едиными настройками train/serve (контракт #1). Производительность:
55 МБ PCAP → 18 315 потоков за ~6 с.

**Модуль `features/windowing.py`** — нарезка окон для CNN+LSTM: группировка по
src_ip, сортировка по event-time, N=16/stride=1, левый паддинг нулями +
bool-маска для прогрева (контракт #7), индексы последних потоков для меток.

**Модуль `features/labeling.py`** — перенос ground-truth меток на
nfstream-потоки (контракт #2). Две найденные и решённые грабли:
1. **Таймзона**: PCAP в UTC, binetflow CTU-13 — в пражском локальном времени
   (CEST, +2 ч). Наивный парсинг сдвинул бы все метки на 2 часа. Решение:
   явная таймзона источника (`Europe/Prague`) с конверсией в UTC.
2. **Старт-к-старту не работает для длинных потоков**: Argus пишет одну
   GT-запись на многочасовой DDoS-флуд, а nfstream режет его по active_timeout
   на сегменты со стартами на десятки минут позже. Решение: матч по
   **интервалу** GT-записи [start, start+Dur] (расстояние до интервала ≤ допуска,
   по умолчанию 60 с), 5-tuple в обеих ориентациях, выбор ближайшей записи.
   На сценарии 10 (DDoS) подняло матч с 54.9% до 64.4%, botnet-примеров — в 2.6
   раза.

**Пайплайн `features/ctu13.py`** (`python -m mlsiem.features.ctu13`) — все 13
сценариев → размеченные parquet (`data/processed/ctu13/`) + `summary.csv`.

Третья грабля (найдена при доводке): **ICMP не матчится по 5-tuple никогда** —
nfstream пишет порты ICMP нулями, Argus кодирует в них тип/код (hex). Решение:
протоколы без портов матчатся по 3-tuple (src_ip, dst_ip, protocol). Дало
+0.9 п.п. к общему матчу (сценарий 3: 86.6% → 90.5%).

**Сценарий 8 (71.7%) — диагноз поставлен, лечению не подлежит:** 91%
несматченных — сканы червя на порт 135 по родной подсети 147.32.84.x.
В GT этих потоков НЕТ физически: Argus у авторов стоял на роутере, а
внутрисетевой трафик через роутер не ходит; наш PCAP писался у заражённой
машины и видит всё. Проверено адресно: в GT есть 4 702 botnet-записи сканов
на :135, но только в чужие подсети (147.32.79.x и др.); 144 dst-адреса родной
подсети в GT отсутствуют полностью. Несматченные потоки честно остаются null.
Возможная опция на будущее (требует решения): фоллбэк «потоки задокументированной
заражённой машины → botnet» — так сами авторы определяют свои метки.

Несматченные потоки получают `label = null` и в обучение не идут — честный
пропуск безопаснее сомнительной метки.

**Тесты:** 19 (юнит + интеграционные с реальным nfstream), CI гоняет их и на
Linux. Санити-проверка данных: в сценарии 1 заражённая машина 147.32.84.165,
топ протоколов — SMTP (8 413 потоков): Neris — спам-ботнет, картина сходится.
