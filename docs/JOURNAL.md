## 2026-06-12 — Фаза 1: данные и фичи (В РАБОТЕ)

**Датасеты** (`A:\datasets\`):
- CSIC 2010 (web-атаки, для Эксперта 3) — скачан с зеркала, проверен:
  сырые HTTP-запросы, в аномальных — SQLi/XSS.
- CTU-13 (13 ботнет-сценариев, для Эксперта 2) — скачан (1.86 ГБ) и распакован:
  в каждом сценарии ботнет-PCAP + ground-truth `.binetflow` (+ образец малвари —
  не запускать!).
- UNSW-NB15 (~100 ГБ PCAP + CSV GT, для Эксперта 1) — качается;
  Argus/BRO-выгрузки авторов сознательно не берём (контракт #1: фичи считаем
  сами, nfstream'ом).

**Модуль `features/extractor.py`** — переэкстракция PCAP → потоки (86 фич) через
nfstream с едиными настройками train/serve (контракт #1). Производительность:
55 МБ PCAP → 18 315 потоков за ~6 с.

**Модуль `features/windowing.py`** — нарезка окон для CNN+LSTM: группировка по
src_ip, сортировка по event-time, N=16/stride=1, левый паддинг нулями +
bool-маска для прогрева (контракт #7), индексы последних потоков для меток.

**Модуль `features/labeling.py`** — перенос ground-truth меток на
nfstream-потоки (контракт #2). Две найденные и решённые грабли:
1. **Таймзона**: PCAP в UTC, binetflow CTU-13 — в пражском локальном времени
   (CEST, +2 ч). Наивный парсинг сдвинул бы все метки на 2 часа. Решение:
   явная таймзона источника (`Europe/Prague`) с конверсией в UTC.
2. **Старт-к-старту не работает для длинных потоков**: Argus пишет одну
   GT-запись на многочасовой DDoS-флуд, а nfstream режет его по active_timeout
   на сегменты со стартами на десятки минут позже. Решение: матч по
   **интервалу** GT-записи [start, start+Dur] (расстояние до интервала ≤ допуска,
   по умолчанию 60 с), 5-tuple в обеих ориентациях, выбор ближайшей записи.
   На сценарии 10 (DDoS) подняло матч с 54.9% до 64.4%, botnet-примеров — в 2.6
   раза.

**Пайплайн `features/ctu13.py`** (`python -m mlsiem.features.ctu13`) — все 13
сценариев → размеченные parquet (`data/processed/ctu13/`) + `summary.csv`.

Третья грабля (найдена при доводке): **ICMP не матчится по 5-tuple никогда** —
nfstream пишет порты ICMP нулями, Argus кодирует в них тип/код (hex). Решение:
протоколы без портов матчатся по 3-tuple (src_ip, dst_ip, protocol). Дало
+0.9 п.п. к общему матчу (сценарий 3: 86.6% → 90.5%).

## 2026-06-15 — Фаза 2: Эксперт 1 (Flow CNN+LSTM) — ЗАКРЫТА (baseline)

**Инфраструктура:** MLflow (SQLite-бэкенд, `mlops/tracking.py`); torch-датасет с
ленивой нарезкой окон и LabelEncoder; модель Flow CNN+LSTM (эмбеддинги категорий
→ Conv1D по фичам потока → LSTM с корректным маскированием прогрева → softmax);
focal loss; тренировочный цикл с AMP, early stopping по val PR-AUC, per-class
метриками. Тестов в сюите: 47.

**Решённые проблемы по ходу:**
- Маскирование прогрева: окна паддятся слева, а pack_padded_sequence ждёт
  паддинг справа → сдвиг реальных потоков в начало с сохранением порядка
  (тест инвариантности к паддингу).
- Дисбаланс: plain-обучение схлопывалось в «всё benign» (macro PR-AUC 0.13,
  train_loss≈0). Лечение — **class-balanced sampling** (вес ∝ 1/√частота) →
  macro 0.44.
- Скорость/процессы: на Windows-venv multiprocess-загрузка путала картину
  процессов (лаунчер + интерпретатор выглядят как два main) → `num_workers=0` +
  оптимизация `__getitem__` (вьюхи окон, предпосчёт масок).
- CI: новые torch-тесты падали на CI (torch не ставился) → шаг установки
  CPU-torch + extra `[ml]`.

**Baseline (UNSW, хронологический сплit 80/20), лучшая эпоха, val PR-AUC:**

| Класс | PR-AUC | Класс | PR-AUC |
|---|---:|---|---:|
| benign | 1.000 | generic | 0.296 |
| reconnaissance | 0.920 | dos | 0.145 |
| exploits | 0.777 | backdoor | 0.112 |
| shellcode | 0.616 | analysis | 0.074 |
| fuzzers | 0.476 | worms | 0.014 |

**macro PR-AUC = 0.443.** Артефакты: `mlartifacts/flow_cnn_lstm/`
(flow_cnn_lstm.pt + preprocessor.json + label_encoder.json), прогон в MLflow.

**Вывод (ключевой для отчёта):** flow-эксперт уверенно детектит атаки с явной
сетевой сигнатурой (recon 0.92, exploits 0.78, shellcode 0.62), но почти слеп к
скрытным/редким (worms 0.01, analysis 0.07, backdoor 0.11, dos 0.15) — **ровно
урок v1 и тезис плана о потолке flow-фич**. Это не повод «чинить датасет»:
слепые зоны закрывают payload-эксперт (Э3), host-эксперт (Э5) и AE/open-set
(Э4). Даже слабые классы выше случайного (worms 0.014 vs ~0.0001 random) —
модель не пустая.

**Замечания на будущее (не блокируют):** лучший результат на эпохе 0 с
последующим спадом → агрессивный оверсэмплинг переобучает; кандидаты на
улучшение — мягче сэмплинг/регуляризация/ниже lr. benign отделяется тривиально
(1.0) — сложность в мультиклассовой дискриминации атак, а не в «атака/норма».

## 2026-06-15 — Фаза 3: Эксперт 4 (Conv1D Autoencoder) — ЗАКРЫТА (baseline + оговорка)

**Модель:** Conv1D AE по окну [N,F], узкое горлышко 64 (4×16), без Flatten/
GlobalAvgPool (рецепт v1). Маскированная MSE (паддинг не штрафуется). Обучение
ТОЛЬКО на benign (подвыборка 200k окон), порог по целевому FPR 5% (не «70-й
перцентиль» — урок v1). Тестов в сюите: 52.

**Найден и исправлен латентный баг препроцессинга (важно для всего проекта):**
у почти-константных фич std≈0 делился на `_STD_FLOOR=1e-6` → крошечное
отклонение на serve давало астрономический z-score, val_recon взрывался до
82005. Лечение: константы (std<1e-2) дают нулевой вклад; нормализованные
значения клипаются в [-10,10] + защита от non-finite. Затрагивало и Э1 (его
baseline 0.443 снят ДО фикса → переснять).

**Результат (UNSW, полный held-out):** ROC-AUC = 0.980, PR-AUC = 0.551; при
FPR 5% recall: worms 1.00, shellcode 1.00, fuzzers 1.00, recon 1.00, generic
0.99, exploits 0.99, dos 0.99, backdoor 0.99, analysis 0.81.

**⚠️ Оговорка (ключевая для отчёта — НЕ принимать 0.98 за чистую монету):**
AE одинаково «детектит» и волюметрический dos, и СКРЫТНЫЙ backdoor/worms — а по
тезису плана AE должен быть слаб на скрытных. Это сигнал, что AE различает не
«атака vs норма», а **источник трафика**: в UNSW benign и атаки сгенерированы
разными инструментами (IXIA benign-профиль vs attack-модуль), и AE выучил
«трафик benign-генератора». Артефакт синтетического датасета, который **не
перенесётся** на полигон, где benign (GHOSTS) и атаки в одной среде. Поэтому
план и требует «норму» AE из полигона (фаза 19). **UNSW-AE = претрейн/санити,
не финальный детектор.** Реальная проверка AE — на лаб-данных (фаза 19/21).

**Артефакты:** `mlartifacts/autoencoder/` (autoencoder.pt + preprocessor +
encoder), прогон в MLflow. Сходимость чистая (train 0.082 / val 0.087, без
переобучения).

## 2026-06-15 — Followup: переобучение Э1 с исправленным препроцессингом

Поскольку фикс препроцессинга (клип + константы) затронул и Э1, переобучили его.
Результат: macro PR-AUC **0.437** против прежних 0.443 — **без материальных
изменений** (в пределах шума прогона). Вывод: supervised flow-классификатор был
устойчив к std-floor багу (выбросы редки, не доминировали); фикс критичен для AE
(чувствителен к величине recon на окно), но нейтрален для Э1. **Подтверждено:
потолок ~0.44 — настоящий потолок flow-фич, а не артефакт нормализации.**
Слабость на скрытных классах препроцессингом не лечится — только другими
представлениями (payload Э3 / host Э5). Baseline Э1 в карте покрытия остаётся в
силе.

## 2026-06-15 — Фаза 4: Мета-слой на правилах (MVP-детект) — ЗАКРЫТА

**Код:** `detection/meta.py` — детерминированные правила объединения Flow+AE:
уверенная атака Flow (max-prob≥τ) → его класс; corroboration (Flow+AE на одном
окне) → выше confidence; Flow не уверен/benign + AE high → **open-set UNKNOWN**;
severity-движок класс→критичность. `detection/experts.py` — загрузка Flow+AE с
общим препроцессором, единый инференс по окну. `detection/evaluate_mvp.py` —
сравнение меты с одиночными экспертами. Тестов в сюите: 60 (9 на мету).

**MVP-оценка (UNSW held-out, 205 889 окон, 16 323 атаки; AE-порог калиброван на
отдельной половине):**

| Детектор | recall | FPR | precision |
|---|---:|---:|---:|
| Flow-only | 0.994 | 0.056 | 0.605 |
| AE-only | 0.997 | 0.093 | 0.480 |
| МЕТА (OR) | 0.998 | 0.093 | 0.480 |

**Находки (ценнее самих цифр):**
- Recall ~0.99 у всех — артефакт UNSW (оговорка фазы 3), не финальное качество.
- **Open-set работает:** мета поймала 94 атаки, пропущенные Flow (AE подстраховал
  слепые зоны). Severity-тиры заполняются (critical 62, high 4203, medium/low —
  основная масса).
- **Цена наивного OR:** мета унаследовала FPR худшего эксперта (0.093 vs 0.056 у
  Flow) и просадку precision (0.605→0.48). Слепое «ИЛИ» максимизирует recall
  ценой ложных. → мотивирует обучаемый **stacking-мета (фаза 7)** вместо правил.
- **Дрейф калибровки:** порог под 5% FPR на калибе дал 9.3% на тесте → калибровать
  на распределении ближе к serve (контракт #11).
- Flow precision 0.60 — следствие class-balanced обучения (сдвиг к атакам): высокий
  recall ценой precision на реальном дисбалансе. Тоже в работу для меты v2.

**Вертикальный срез готов:** PCAP → фичи → окна → 2 эксперта → единый вердикт
{class, severity, confidence}. Это вход для SOAR (фаза 8).

## 2026-06-15 — Фаза 5 (Temporal/Э2): ОТЛОЖЕНА до полигона — решение

При подготовке обучения вскрылось ограничение данных: извлечённые фичи CTU-13
взяты из `botnet-capture-*.pcap`, где трафик на **94% ботнет** (botnet 218 760,
background 13 855, normal 11, не размечено 8 919). Полноценный benign/background
CTU-13 живёт в исходных binetflow (миллионы строк), но в публичных ботнет-pcap
не-ботнет-трафик урезан до заголовков (приватность) — пакетов для nfstream нет.

**Почему нельзя обучить чистого Э2 сейчас:** при botnet=94% детектор вырождается
(«всегда ботнет» ⇒ тривиальные 94%), PR-AUC неинформативен. Вариант «влить
CTU-ботнет в Flow + benign из UNSW» даёт кросс-датасетный конфаунд (модель учит
«CTU vs UNSW», а не «ботнет vs норма») — тот же артефакт, что у AE (контракт #6).

**Решение (согласовано):** отложить Э2 до фазы 19 (полигон), где benign (GHOSTS)
и ботнет-beaconing будут в ОДНОЙ среде → temporal-эксперт обучится без конфаунда.
CTU-13 пока остаётся референсом ботнет-поведения. Вопрос слияния Э1+Э2 (план,
раздел 4) тоже переносится на момент, когда появятся консистентные benign-данные.
В карте покрытия Э2 помечен как отложенный.

Технически: в тренировочный скрипт добавлен `--label-col` (UNSW=canonical,
CTU-13=label_class) — пригодится позже; build_datasets отбрасывает потоки без
метки (unmatched). Переходим к фазе 6 (Payload/Э3 на CSIC — данные полноценные).

## 2026-06-15 — Фаза 6: Эксперт 3 (Payload char-CNN на CSIC) — ЗАКРЫТА

**Данные:** парсер `features/csic.py` — 97 065 HTTP-запросов (normal 72 000 /
anomalous 25 065), текст = METHOD+URL+тело POST (заголовки-шум отброшены),
percent-encoding как есть. Сбалансировано, обе метки из одной среды.

**Модель:** `models/payload/` — посимвольный токенизатор (0=PAD, 1=UNK,
max_len=512) + char-CNN (embedding → Conv1d ядер 3/5/7 → global max-pool →
softmax). Тестов в сюите: 71 (+11 на CSIC/payload).

**Результат (CSIC, стратиф. сплit 80/20):** PR-AUC **0.9998**, recall 0.99,
precision 0.99. Лучшая эпоха 13.

**Проверка на «слишком хорошо» (в отличие от AE — результат подлинный):**
- Нет кросс-датасетного конфаунда: normal/anomalous из ОДНОЙ среды, по источнику
  читерить нельзя.
- Сходимость ПЛАВНАЯ за 14 эпох (loss 0.20→0.004) — тривиальный шорткат (длина
  запроса) выучился бы мгновенно на эпохе 0; постепенное обучение = реальные
  символьные паттерны (`'`, `;`, DROP, `<script>`).
- ~0.99 на CSIC — типично для литературы (датасет хорошо разделим).

**Оговорка:** CSIC — одно синтетическое веб-приложение; 0.9998 — in-distribution.
Перенос на другие приложения/payload не проверен (план: HTTP MVP → reverse-proxy
TLS на полигоне). Char-level должен обобщаться лучше word-level (SQLi/XSS
символьно-инвариантны к приложению).

**Покрытие:** Э3 ЗАКРЫВАЕТ web-зону (SQLi/XSS/brute), слепую для Flow и AE —
первый эксперт, реально расширяющий покрытие за пределы flow. Артефакты:
`mlartifacts/payload/` (payload_charcnn.pt + tokenizer + encoder).

**Итог:** 3 рабочих эксперта (Flow + AE + Payload). Следующий логичный шаг —
фаза 7 (stacking-мета вместо наивного OR, чтобы учесть разную надёжность
экспертов по классам).
